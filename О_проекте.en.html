Method

What sits behind the system

Every recommendation is tied to a publication in a peer-reviewed journal. Evidence grades are assigned by hand, not automatically: where there is no meta-analysis, an honest D is used rather than an inflated A.

How it is put together

How it is built

Three sources

Three files are the sources of truth: db_сферы.js (the questionnaire, its questions and actions), db_советы.js (findings about the body) and db_советы_жизнь.js (money, relationships, work, mind, daily life). The builder, the bot, the reference and this page are all built from them.

One style

The design system lives in style_system.mjs. One constant changes the accent across every file.

Checks

Functional tests and contrast checks run in a real browser with a single command.

node build_all.mjs            rebuild the advice base
node wire_spheres.mjs          embed the life questionnaire
node build_site.mjs            rebuild the site
node run_checks.mjs            all checks at once
Limits

What the system does not do

It does not replace a doctor

Blood tests, diagnoses, treatment decisions and prescriptions belong to a specialist. The health section of the plan is a route to a doctor, not a prescription. Money, relationships and the mind work the same way: the roadmap suggests a first step, a real person decides.

It does not upload data

All calculations run in the browser. The genome file is processed locally by a script and never transmitted.

It needs its window open

The bot lives as long as its program is open. Permanent operation needs a host — see the bot page.

It does not guarantee results

Year-end expectations are given as a range for home training. It is a reference point, not a promise. A sphere score is not a diagnosis: it is the answers to seven questions, used to decide where to start.

Everything is calculated locally and no data is uploaded. The bot is a reminder, not a doctor: blood tests, diagnoses and treatment decisions belong to a specialist.
